# ADR-0033: Angular client — PKCE sign-in, streamed answers, generated contract

- **Status:** Accepted
- **Date:** 2026-11-17
- **Deciders:** project owner

## Context

Step 13 adds the first user interface. Its exit criterion: *a user uploads a document, waits
for indexing, asks questions, and inspects citations.* The API was already complete and
secured (ADR-0031: JWT from an OIDC issuer; Keycloak locally, with a public client `eka-cli`
prepared for authorization code + PKCE). The learning path names streaming answers (SSE) as
a concept of this step. Four choices were open: how the browser signs in, whether answers
stream, which UI kit, and where the client lives. The owner chose the recommended option for
each.

## Decision

1. **Sign-in: `angular-auth-oidc-client` (OpenID-certified), code flow + PKCE** against the
   same issuer and scope the API validates. Refresh-token renewal (not iframe), tokens in
   `sessionStorage`, the interceptor attaches tokens to the API origin only (`secureRoutes`).
2. **Answers stream as server-sent events** from a second route,
   `POST /api/conversations/{id}/messages/stream`, sharing the handler with the JSON route:
   - `IChatCompletionService.StreamAsync` returns the same `Result<ChatCompletion>` and hands
     deltas to a callback. Default interface implementation = one delta (an adapter that
     cannot stream still works).
   - Events: `delta` (raw model text, display only), then exactly one `completed` (the
     persisted exchange — renumbered citations) or `error` (a problem document; nothing
     persisted).
   - **The response starts on the first event.** Failures before it keep their HTTP status
     (404, 429, 502); only failures after text was shown travel in-band. Hence a hand-written
     writer, not `TypedResults.ServerSentEvents`, which commits a 200 immediately.
   - The client reads it with `fetch` (EventSource cannot POST or send a bearer token) and
     hides `[n]` markers until `completed`, because they are renumbered.
3. **UI: Angular Material 21 (M3)**, standalone components, signals, zoneless. Model output is
   rendered as text only — markers become buttons, nothing goes through `innerHTML`.
4. **Location: `src/EKA.Web` in this repository.** Types are generated by
   `openapi-typescript` from a **checked-in** OpenAPI document (`openapi/eka-api.json`). An
   integration test fails when the running API's document differs from it; `npm run
   check:api` fails when the generated types differ from the document. The API is
   `JsonNumberHandling.Strict`, so integers are `number`, not `number | string`.
5. `DocumentResponse.CanManage` / `DocumentSummaryResponse.CanManage`: the server answers
   "may this caller manage it?" with the aggregate's own rule, so the client shows controls
   without re-implementing authorization. The handlers still enforce it.

## Consequences

### Positive

- One handler, one atomic turn, two transports: streaming adds no second code path for
  retrieval, grounding or persistence.
- A contract change cannot silently drift: server snapshot test → regenerated types → `tsc`.
- No secret in the browser; PKCE and refresh rotation are the library's, not ours.

### Negative / costs we accept

- **Access tokens are readable by script** (sessionStorage). An XSS would expose them. The
  mitigations are no HTML rendering of model output and a strict CSP (Step 14), not
  elimination.
- The chat port grew a member (ADR-0016's port is still in domain vocabulary).
- Two ask routes to keep in step (same rate limit and validation are attached to both).
- Deltas cost a write+flush each; an answer is hundreds of small writes.
- Polling (every 3 s while anything is indexing) instead of push for ingestion status.

## Alternatives considered

- **Backend-for-frontend** (tokens on the server, cookie to the browser): wins for a
  production deployment handling sensitive data, where token theft by XSS is unacceptable —
  the IETF browser-app BCP ranks it first. Costs a server component, cookie auth + CSRF.
- **`oidc-client-ts` wrapped by hand:** wins only if the certified Angular library cannot do
  something required.
- **No streaming:** wins if perceived latency does not matter or a proxy in the path cannot
  stream; simpler and cheaper to test. The JSON route remains for that.
- **`TypedResults.ServerSentEvents`:** wins if every failure may legitimately be in-band.
- **WebSockets / SignalR:** wins for bidirectional or server-initiated traffic (e.g. pushing
  ingestion status); overkill for one request → one streamed response.
- **Headless/CSS-only UI:** wins with a bespoke brand; we would own all accessibility work.
- **Separate repository / generated client services (NSwag, ng-openapi-gen):** a separate
  repo wins when another team releases the client independently; generated services win
  when the API surface is large enough that hand-written thin services become the cost.

## Revisit when

- Deployment to anything shared (Step 14): BFF vs CSP-hardened SPA, and token storage.
- A reverse proxy or gateway buffers responses (streaming silently degrades to one chunk).
- Indexing waits regularly exceed a minute, or many users watch the list: push instead of poll.
- The API surface grows past ~30 operations: generated services instead of thin wrappers.
